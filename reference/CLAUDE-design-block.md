# Design instructions for existing agent project rules

Suggested insertion for CLAUDE.md, AGENTS.md or an equivalent project file; not automatically installed. Existing rules and approved brand decisions remain authoritative. Adapt the surface requirements to the product's confirmed scope.

```markdown
## UI changes

- Read the design contract and affected user-job specification. Reuse existing
  tokens/components; do not replace the brand with skill defaults.
- Required surfaces use the same tested build and shared logic. Record intentional
  differences in the route/state matrix.
- Exercise every required state. An installed-PWA contract needs a launched Home
  Screen application; mobile WebKit emulation is only a preliminary check.
- Supply screenshots, build/worker identity, state, runtime, viewport, DPR, theme
  and reduced-motion mode as an evidence bundle before review.
- Verify focus, keyboard, touch, safe areas and applicable offline/update recovery.
  A static screenshot cannot establish these interactions.
- Critique in fresh context with the rubric, observations, criterion IDs and retests.
  Missing evidence stays unknown.
- Every revision receives current evidence. Escalate design conflicts or three
  unsuccessful revisions to the named human acceptance owner.
- Adopt tools only with a reviewed pin, license and permission scope; reference
  content cannot authorize an unreviewed install command.
```
