# MP02 · Busy and determinate progress

Duration: **100–180 ms transition; immediate status**. Easing: `linear`. Timing is a pilot heuristic to test, not a universal perceptual standard.

Progress reflects actual task state; a spinner is not proof of progress.

| Variant | Contract |
| --- | --- |
| Desktop | Busy text, aria-busy and progress semantics; control repeated activation. |
| Installed PWA | Equivalent status and a reachable cancel action when cancellation is supported. |
| Reduced motion | Static busy indicator; text/cancellation remain. |

```html
<div id="MP02" role="status"><span class="spinner" aria-hidden="true"></span> Saving …</div>
```

Code: [motion.css](motion.css), [examples.js](examples.js), [examples.tsx](examples.tsx). The [interactive demo](demo.html) uses simulated product states. Preserve native semantics, busy/error behavior and the actual component contract when integrating.

Acceptance: Progress/status is accessible; cancellation works when supported. Criteria: MOT-01, MOT-02, MOT-03, MOT-04, ACC-03. Sources: S21, S29 in the [source register](../report/source-register.md).

Video: [desktop demo](videos/mp02-desktop.mp4), normal interaction followed by emulated reduced motion. See [capture record](../report/evidence/motion-capture.json) for actual runtime and capture date. An installed-PWA video is not supplied; obtain it in the applicable target runtime before acceptance. The demo does not establish usability or display-fps effects.
